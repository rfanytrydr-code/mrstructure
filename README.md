# MrStructure — وب‌سایت واقعی (نسخه MVP)

این پروژه، نسخه قابل اجرا و قابل استقرار سایت مستر استراکچر است. برخلاف فایل HTML اولیه، داده‌ها فقط در مرورگر ذخیره نمی‌شوند؛ ثبت‌نام، ورود، سفارش‌ها، پیام‌ها و فایل‌ها از طریق سرور مدیریت می‌شوند.

## امکانات فعلی
- صفحه اصلی فارسی و واکنش‌گرا (RTL)
- ثبت‌نام و ورود؛ رمزها با bcrypt هش می‌شوند
- نقش کاربر و مدیر؛ ایجاد اولین مدیر از طریق متغیرهای محیطی
- ثبت درخواست رفع اشکال، حل تمرین و آموزش خصوصی
- شماره پیگیری یکتا و تاریخچه تغییر وضعیت
- بارگذاری/دانلود PDF، JPG و PNG (حداکثر ۱۰ فایل و ۱۰ مگابایت برای هر فایل)
- پنل کاربر و پنل مدیریت برای مشاهده سفارش‌ها، تغییر وضعیت و مبلغ
- پیام‌های مرتبط با هر سفارش
- SQLite برای داده‌ها، کوکی جلسه امضاشده، محدودسازی تلاش‌های ورود و هدرهای امنیتی پایه

## اجرای محلی
نیازمند Node.js نسخه 20 یا جدیدتر است.

```bash
npm install
```

فایل `.env.example` را به `.env` کپی کنید و رمز مدیر را به یک رمز قوی تغییر دهید. سپس متغیرهای محیطی را در شل خود تنظیم کنید یا از ابزاری مانند `dotenv` استفاده کنید. پروژه فایل `.env` را هنگام شروع بارگذاری می‌کند؛ متغیرهای تنظیم‌شده در محیط استقرار نیز قابل استفاده‌اند.

Linux/macOS:
```bash
export SESSION_SECRET="یک-رشته-تصادفی-طولانی-حداقل-۳۲-کاراکتر"
export ADMIN_USERNAME="admin"
export ADMIN_PASSWORD="یک-رمز-قوی-حداقل-۱۲-کاراکتر"
npm start
```

Windows PowerShell:
```powershell
$env:SESSION_SECRET="یک-رشته-تصادفی-طولانی-حداقل-۳۲-کاراکتر"
$env:ADMIN_USERNAME="admin"
$env:ADMIN_PASSWORD="یک-رمز-قوی-حداقل-۱۲-کاراکتر"
npm start
```

سپس آدرس `http://localhost:3000` را باز کنید. در اجرای محلی، اگر رمز مدیر را تنظیم نکنید، برنامه از شروع با رمز ضعیف خودداری می‌کند؛ مقدار پیش‌فرض محلی فقط برای توسعه است و نباید در اینترنت استفاده شود.

## استقرار روی Render
1. این پوشه را در یک مخزن خصوصی GitHub قرار دهید.
2. در Render یک **Web Service** بسازید و مخزن را متصل کنید.
3. Build Command: `npm install`
4. Start Command: `npm start`
5. متغیرهای `NODE_ENV=production`، `SESSION_SECRET` (رشته تصادفی بلند)، `ADMIN_USERNAME` و `ADMIN_PASSWORD` را اضافه کنید.
6. یک **Persistent Disk** اضافه کنید، مثلاً با mount path برابر `/var/data`.
7. `DATA_DIR=/var/data` و `UPLOAD_DIR=/var/data/uploads` را تنظیم کنید. مسیر `UPLOAD_DIR` داخل دیسک پایدار باشد تا فایل‌ها پس از استقرار مجدد حذف نشوند.
8. پس از اولین راه‌اندازی، با حساب مدیر وارد شوید. رمز مدیر را در جای امن نگه دارید.

اگر از میزبانی دیگری استفاده می‌کنید، باید Node.js را پشتیبانی کند و برای SQLite و فایل‌های بارگذاری‌شده فضای ذخیره‌سازی پایدار داشته باشد. فایل‌های SQLite و uploads را روی دیسک موقت سرویس قرار ندهید.

## نکات پیش از انتشار عمومی
- اطلاعات تماس، متن‌ها، دامنه و سیاست حریم خصوصی را نهایی کنید.
- از HTTPS استفاده کنید (Render آن را فراهم می‌کند).
- برای سایت پرترافیک یا چند سرور، PostgreSQL و فضای ذخیره‌سازی شیءگرا مانند S3 مناسب‌تر از SQLite/دیسک محلی است.
- این نسخه پرداخت آنلاین، ایمیل تأیید، بازیابی رمز عبور، CAPTCHA و اتصال خودکار به تلگرام ندارد.
- برای بارگذاری فایل‌ها، سرور پسوند و MIME را بررسی می‌کند؛ با این حال در انتشار عمومی جدی، اسکن ضدبدافزار و سیاست نگهداری/حذف فایل نیز اضافه کنید.
- فایل `original-project.html` نسخه HTML اولیه شماست که برای مرجع در بسته نگه داشته شده است؛ سایت اجرایی در `public/index.html` قرار دارد.
